SOLID · IVP

Marco formal basado en el Principio de Variación Independiente  ·  Axiomas → Teorema → Corolarios (SOLID) con notación y ejemplos

📐 Notación formal

Definiciones
  • E = { e₁, e₂, … } — Elementos (clases, módulos)
  • Δ = { δ₁, δ₂, … } — Drivers de cambio
  • cd(e) ⊆ Δ — Drivers que afectan a e
  • D ⊆ E × E — Dependencias (eᵢ, eⱼ) ∈ D
  • inh(e₁, e₂) — e₁ hereda de e₂
  • comp(e₁, e₂) — e₁ compone a e₂
  • Pre(m), Post(m) — Precondición y postcondición
  • I — Conjunto de interfaces (I ⊆ E)

→ Esta notación se usa en todos los teoremas y corolarios.

📜 Axiomas fundamentales

Axioma 1 Abstracción

“Programa para una interfaz, no para una implementación”

∀ cliente c ∈ E, ∀ implementación impl ∈ E | (c, impl) ∈ D
∃ abstracción a ∈ I // a oculta los drivers de impl
tal que cd(a) ⊂ cd(impl) ∧ (c, a) ∈ D ∧ (a, impl) ∈ D

El cliente c depende de la abstracción a, que encapsula los drivers de la implementación.

Axioma 2 Composición sobre herencia

“Favorece la composición frente a la herencia”

Dadas inh(e₁, e₂) y comp(e₁, e₂),
preferimos comp si ∃ a ∈ I | cd(a) ⊂ cd(e₂) ∧ (e₁, a) ∈ D

La composición permite depender de una abstracción, reduciendo el acoplamiento a los drivers del componente.

🧠 Teorema central: IVP

Teorema 1 Principio de Variación Independiente

“Los elementos con los mismos drivers de cambio pertenecen juntos; los elementos con diferentes drivers pertenecen separados.”

∀ e₁, e₂ ∈ E :
cd(e₁) ∩ cd(e₂) ≠ ∅ → e₁ y e₂ deben estar en el mismo módulo
cd(e₁) ∩ cd(e₂) = ∅ → e₁ y e₂ deben estar en módulos separados

✔ Equivalencia lógica bidireccional con SOLID: IVP ⇔ (SRP ∧ OCP ∧ LSP ∧ ISP ∧ DIP)

Demostración conceptual: Minimizar el coste de propagación de cambios en el grafo de incidencia es equivalente a agrupar elementos por driver común y separar los que tienen drivers disjuntos.

📌 Corolarios: Principios SOLID

S Responsabilidad Única (SRP)

Corolario 1: Una clase debe tener una única razón para cambiar.

∀ c ∈ E : |cd(c)| = 1

Derivación: Aplicación directa del Teorema IVP al nivel de clase. Si |cd(c)| > 1, la clase responde a múltiples drivers, violando la agrupación por driver común.

O Abierto/Cerrado (OCP)

Corolario 2: Las entidades deben estar abiertas para extensión, cerradas para modificación.

∀ módulo M, ∀ driver δ ∈ Δ :
si δ introduce una nueva variante v, entonces v se añade como nuevo subtipo de una abstracción a,
sin modificar M. // M depende de a (Axioma 1)

Derivación: Teorema IVP + Axioma 1. Las variantes de un driver deben ser elementos separados pero agrupados por su driver común; el cliente depende de la abstracción que las oculta.

L Sustitución de Liskov (LSP)

Corolario 3: Los objetos de una clase derivada deben poder sustituir a los de su clase base sin alterar el comportamiento.

∀ s, t ∈ E | inh(s, t) :
Pre(ms) ≤ Pre(mt) // precondición no más fuerte
Post(ms) ≥ Post(mt) // postcondición no más débil

Derivación: Condición necesaria para que la abstracción del Axioma 1 sea sustituible. Si un subtipo rompe el contrato, los clientes que dependen de la abstracción ven alterado su comportamiento, violando el IVP.

I Segregación de Interfaces (ISP)

Corolario 4: Es mejor tener muchas interfaces específicas que una interfaz general.

∀ cliente c, ∀ interfaz i | (c, i) ∈ D :
c solo debe depender de los métodos de i que realmente usa.
Si i es “gorda”, entonces ∃ i₁, i₂, … con cd(iⱼ) ∩ cd(iₖ) = ∅ para j≠k.

Derivación: Corolario directo del Teorema IVP. Una interfaz “gorda” expone a los clientes a drivers que no les afectan; debe segregarse según los drivers.

D Inversión de Dependencias (DIP)

Corolario 5: Depender de abstracciones, no de implementaciones concretas.

∀ módulo alto h, módulo bajo l :
¬ (h, l) ∈ D // h no depende de l
∃ a ∈ I | (h, a) ∈ D ∧ (l, a) ∈ D // ambos dependen de la abstracción

Derivación: Aplicación directa del Axioma 1. Es el mecanismo principal para aislar módulos de alto nivel de los drivers de los módulos de bajo nivel, cumpliendo así el IVP.
